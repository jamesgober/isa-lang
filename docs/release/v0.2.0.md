# isa-lang v0.2.0 — x86-64 Machine Code, From a Table

**The foundation.** v0.2.0 turns the scaffold into the x86-64 encoding layer
of the family's native backend: a target description of 340 instruction forms
covering the integer, control-flow, and memory core, one table-driven encoder
and one decoder that interpret it, a deterministic Intel-syntax disassembler,
and an assembler with labels and optimal branch relaxation. No dependencies,
no `unsafe`, `no_std` with `alloc`.

## What is isa-lang?

The last step of a native compiler backend that is ours end to end: the
instruction selector and register allocator (backend-lang) decide what to
run; isa-lang turns it into exact bytes, decodes bytes back for testing and
debugging, and prints them. It is a CODE-tier crate in the `-lang` family and
replaces the encoding half of the rented Cranelift backend that jit-lang 1.x
uses. AArch64 joins in 0.5.0 under the same model.

## What's new in 0.2.0

### The target description

Every form is one row, written as the Intel SDM's opcode tables write it:

```rust,ignore
row("REX.W 83 /0 ib",  "ADD r/m64, imm8",  ARITH),
row("0F 80+cc cd",     "Jcc rel32",        COND),
row_a("50+rd",         "PUSH r64",         NONE, ATTR_D64),
```

A `const fn` compiles the rows while the crate builds, checking that each
recipe and signature describe the same fields; a malformed row is a compile
error. Two indexes (by mnemonic, by opcode byte) are built the same way. The
table is public as data through `forms()`: each `Form`'s encoding recipe,
operand kinds, and flag effects. The model, the engines, and how AArch64's
fixed 32-bit encodings fit it are specified in
`_lexersketch/specs/TARGET-DESC.md`.

### Encoding and decoding

```rust
use isa_lang::x86_64::{decode, encode, Inst, Mem, Mnemonic, Reg, Size};

let load = Inst::new(Mnemonic::Mov, [Reg::RAX.into(), Mem::new(Size::Qword, Reg::RDI).with_disp(16).into()]);
let bytes = encode(&load)?;
assert_eq!(&*bytes, [0x48, 0x8B, 0x47, 0x10]);
assert_eq!(decode(&bytes).unwrap().inst(), load);
assert_eq!(load.to_string(), "mov rax, qword ptr [rdi+0x10]");
# Ok::<(), isa_lang::x86_64::EncodeError>(())
```

- `encode` picks the shortest form that fits and returns the bytes on the
  stack with the form used and its flag effects; `encode_form` emits one
  named form, the door an instruction selector uses.
- `decode` never panics and never allocates; every `DecodeError` names the
  offending byte. `decode_all` walks a buffer; `disassemble` lists one.
- An `Inst` is canonical: immediates are signed values at the operation's
  width (never truncated: out of range is an error), branch targets are
  measured from the instruction's start, and memory operands are addresses.
  Every encoding of the same operation decodes to the same `Inst`.

### The assembler

`Assembler` emits instructions and raw bytes, binds labels, and resolves
`jmp`/`jcc` to labels with relaxation to the least fixed point: every branch
is 2 bytes unless it cannot reach, and no branch is longer than necessary.
`call` and RIP-relative references to labels are patched. Relaxation
re-checks only branches within 256 bytes of each lengthening, with positions
in a Fenwick tree, so it is O(n log n); a 100,000-branch chain in which every
lengthening forces the previous one relaxes in about a quarter of a second in
a debug build.

### Coverage

`mov` (including `imm64`), `lea`, `add or adc sbb and sub xor cmp test`, `inc
dec neg not`, `mul imul div idiv` (`imul` with one, two, and three operands),
`cbw cwde cdqe cwd cdq cqo`, `shl shr sar rol ror` (by 1, `imm8`, `cl`), `movzx
movsx movsxd`, `setcc`, `cmovcc`, `jcc`, `jmp`, `call`, `ret`, `push`, `pop`,
`nop` (and the SDM's recommended 1–9-byte sequences), `ud2`, `int3`, `xchg`,
`bt`, at 8/16/32/64 bits wherever the architecture has the form.

Not yet: floating point and SIMD, `LOCK`/`REP`/segment/address-size prefixes
(so no `fs:`/`gs:` TLS access, planned for 0.5.0), string, system, and far
instructions, and the remaining bit and atomic instructions.

### Tests and verification

- **Every form's operand space.** For each of the 340 forms, every operand
  position is enumerated over its whole candidate space (every register,
  every base × index × scale, every displacement and immediate boundary)
  while the others take representative values, plus every register pair and
  every condition code: over 500,000 instructions. Each must encode with that
  form, decode to the same instruction, form, and length, and the free
  encoder must choose an encoding no longer than it. 20,000 random-operand
  cases cover the space between the boundaries.
- **The decoder on everything.** Every prefix combination × both opcode maps
  × every opcode × every ModRM byte × three SIB/displacement tails (13.4
  million inputs), every 1- and 2-byte input, and 50,000 random inputs: no
  panic; every accepted instruction re-encodes to the same instruction and is
  reported `Truncated` when cut short at any length.
- **The SDM, byte for byte.** 171 known-answer cases with the REX, ModRM,
  and SIB arithmetic written out, plus 12 non-canonical encodings that must
  decode to the canonical instruction.
- **The assembler against a reference.** 3,000 random programs of code,
  branches, calls, RIP-relative loads, and labels, compared byte for byte
  with a naive pass-until-stable relaxation whose bytes are written by hand.
- **Against LLVM (D3: a dev-only oracle, run once while building, not part
  of the suite).** llvm-objdump 18.1.8 disassembled a 195,609-instruction
  sample covering every form and agreed with every length and every
  instruction; it also agreed on all 588,468 instructions the decoder
  accepted from random bytes. clang's integrated assembler produced
  identical bytes for 169 of the 171 known-answer texts; the other two are
  `xchg`, where clang writes the commutative operands the other way round
  (both encodings are correct). On LLVM-decoded random bytes, the decoder
  accepts 88.3% of the instructions that use covered mnemonics; the rest use
  out-of-scope prefixes and opcodes, or carry prefix bits the processor
  ignores, which the decoder rejects by design (`docs/API.md#decoder-acceptance`).

### Dependency wiring

None. isa-lang sits below every crate that will consume it (backend-lang,
jit-lang 2.0, aot-lang 2.0) and needs nothing from the family; pager-lang
(executable memory) is the JIT's concern, not the encoder's. The NOML form of
the description that decision D8 describes is not built: the rows are Rust
data in the same shape, and the reader belongs with backend-lang's pattern
tables. Recorded in `dev/ROADMAP.md`.

## Verification

Run on Windows x86_64, on Rust stable and on the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo build --examples
cargo bench --no-run
```

All green. Counts, identical with all and no default features: 48 unit tests,
25 integration tests (5 of them proptest properties) in four files, and 145
doctests (including every `rust` example in `README.md` and `docs/API.md`).
Linux and the newest toolchain are verified centrally.

Benchmarks (`cargo bench --bench bench`, Windows x86_64, release profile,
100,000-instruction mix shaped like compiler output):

| Benchmark | Per instruction |
|---|---:|
| `encode` (choose the form and encode) | ~40 ns |
| `encode_form` (form already chosen) | ~22 ns |
| `decode` | ~40 ns |
| Intel-syntax text | ~55 ns |
| `Assembler`, loop branch every 16 instructions, through `finish` | ~49 ns |

Two optimizations were measured during the release: rejecting candidate forms
on operand kinds before any layout work (selection-encode −30%, assemble
−38% against the first implementation), and precomputing a form's
memory-only flag for the decoder (−6%).
